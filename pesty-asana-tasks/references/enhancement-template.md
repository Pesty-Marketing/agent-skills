# Website enhancement template

Use this when the client wants something on the website **added or improved** and nothing is broken. Title: `[TAG] P4 | Short description of what's being added or changed`, for example `[EX] P4 | Add testimonial section to service pages`.

Enhancements are scheduled by priority, scope and capacity, not by urgency. (SKILL.md explains why they're always P4.)

The task goes in the **DX** section of the client's main project.

## Description

Fill in each section that applies. Remove the ones that don't. Make each heading an `<h2>`.

```
Summary
  The main point in bold: what's being added or changed, and why it matters to the client.

What's being requested
  A clear description of the addition or change.

Why it's being requested
  The business goal, client preference, competitive pressure or strategic reason.

URLs / pages affected
  Links to the pages that will change.

Design assets or examples
  Mockups, reference sites or visual examples, if there are any.

Success criteria
  What "done correctly" looks like, as conditions someone can check.

Timeline expectation
  Based on the effort estimate (see the table below).

Tradeoffs or risks
  What this might affect: performance, other pages, SEO, maintenance.

Client Override Documentation   (only if Client Override = Yes)
  - What did we recommend?
  - What did the client decide instead?
  - What tradeoffs did we communicate?
  - Proof the client acknowledged it (call recording link, email screenshot).
```

## Custom fields

| Field | How to set it |
|---|---|
| Enhancement Type | Design Refinement, New Feature, Content Update, UX Improvement, Performance Optimization or SEO Enhancement |
| Estimated Effort | Small, Medium, Large or Requires Scoping (see the table below) |
| Business Value | High, Medium or Low: how much this moves the client's results |
| Dependencies | Any that apply: None, Design Needed, Dev Needed, Content Needed, External Vendor, Multiple Teams |
| Original Request Date | The date the client first asked |
| Impact Type | The area of the business this improves |
| Primary Affected Area | Which part of the site |
| Client Override | Yes only if the client chose something other than what we recommended |

## Effort and timeline

| Estimated Effort | Typical timeline |
|---|---|
| Small (under 4 hours) | 5–10 business days |
| Medium (4–16 hours) | 2–3 weeks |
| Large (16+ hours) | 3–4 weeks |
| Requires Scoping | A timeline is given once scoping is done |

Use this table to set the due date and fill in the Timeline expectation section. Don't paste it into the ticket.
